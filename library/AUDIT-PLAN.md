# خطة تدقيق المكتبة القانونية السعودية

## النطاق
- المصدر المستورد: `library/data/saudi-legal-moj.json`، عدد السجلات المعلن 3,185.
- البيانات الأصلية لا تُعدّل أثناء الفهرسة أو التدقيق.
- أي رابط حكومي مسجل هو **مرجع مرشح**، ولا يثبت وحده مطابقة المادة أو سريان التشريع.

## تشغيل التدقيق
من جذر المستودع:
```bash
python3 scripts/audit_library.py
```
ينشئ الأمر `library/data/legal-audit.json` محليًا. افحص التقرير قبل إضافته إلى GitHub، لأنه يتضمن جميع السجلات التي تتطلب مراجعة.

## معايير قبول النشر
1. فحص 3,185 سجلًا فعليًا والتحقق من عددها وعدم فقد أي منها.
2. معالجة أخطاء واجهة البحث والتصفح على الهاتف والحاسب.
3. تدقيق تصنيف التشريعات وعلاقات اللوائح بالأنظمة، ووضع العلاقات غير المؤكدة في قائمة مراجعة.
4. بيان المصدر المسجل لكل سجل؛ تمييز الرابط الحكومي على مستوى التشريع عن الرابط المباشر للمادة.
5. مراجعة الروابط الحكومية والتحقق من وجهتها؛ لا توضع حالة «موثق رسميًا» إلا بعد مطابقة النص والرقم والإصدار.
6. إظهار نتائج التدقيق والنواقص دون إخفائها، وعدم الإيحاء بأن 3,185 مادة تمت مطابقتها رسميًا.
7. بعد نجاح الاختبارات يُدمج طلب المراجعة في `main` ويُتحقق من GitHub Pages.

## حدود التصحيح الآلي
- يُسمح بتوحيد الأسماء لأغراض الفهرسة دون تغيير النص الأصلي.
- لا يُسمح بإزالة سجل مكرر أو دمج نصوص مواد أو استنتاج لائحة تابعة اعتمادًا على التشابه فقط.
- تصحيح النصوص التشريعية يتطلب مستندًا رسميًا محددًا وسجلًا للتغيير.
